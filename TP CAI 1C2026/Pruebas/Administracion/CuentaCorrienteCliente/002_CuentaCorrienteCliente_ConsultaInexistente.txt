
Tipo de prueba: Caja negra / Aceptación
Formulario: Cuenta Corriente Cliente

002_CuentaCorrienteCliente_ConsultaNoExitosa.txt

Objetivo: Validar los escenarios en los que no se puede concretar la consulta de cuenta corriente del cliente.

ACLARACIÓN
Estas pruebas se diseñan desde el punto de vista del usuario. No se evalúa el código interno, sino las entradas ingresadas en pantalla, las acciones realizadas y los resultados visibles esperados.

DATOS DE REFERENCIA

- 33-63761744-9 - Adidas S.A.
- 30-64621216-9 - Nike S.A.
- 24078369 - Marcelo Gallardo

Controles principales del formulario:
- Campo CUIT / DNI / CUIL
- Botón Buscar Cliente
- Selector Fecha Desde
- Selector Fecha Hasta
- Botón Buscar
- Grilla/ListView de movimientos
- Campo Saldo
- Botón Cancelar

========================================================================================================
CASO DE PRUEBA 1
========================================================================================================
Nombre:
Consulta de Cuenta Corriente sin informar cliente

Objetivo:
Verificar que el sistema no permita consultar la cuenta corriente si no se ingresa CUIT, CUIL o DNI.

Datos de Entrada:
- CUIT / DNI / CUIL: vacío
- Fecha Desde: 01/01/2026
- Fecha Hasta: 10/06/2026

Precondiciones:
- El formulario se encuentra abierto.
- No hay cliente cargado.

Pasos:
1. Dejar vacío el campo CUIT / DNI / CUIL.
2. Presionar el botón Buscar Cliente.

Resultado Esperado:
- El sistema informa que el CUIT, CUIL o DNI del cliente no puede estar vacío.
- No se muestra razón social.
- No se cargan movimientos.
- El saldo permanece vacío o en cero.
- La consulta no se concreta.

Resultado Obtenido: El sistema informa que que el CUIT, CUIL o DNI del cliente no puede estar vacío.

CRITERIO DE ACEPTACIÓN DE LOS CASOS NO EXITOSOS

Los casos no exitosos se consideran aprobados si:
- El sistema muestra mensajes claros de validación.
- No se cargan movimientos cuando los datos son inválidos.
- No se calcula saldo cuando la consulta no corresponde.
- El formulario no se bloquea ni se cierra inesperadamente.
- El usuario puede corregir los datos y volver a intentar la consulta.
