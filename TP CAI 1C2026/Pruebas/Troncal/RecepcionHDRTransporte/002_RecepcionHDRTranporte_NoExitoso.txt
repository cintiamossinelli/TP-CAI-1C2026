
PLAN DE PRUEBAS DE CAJA NEGRA - RECEPCIÓN HDR TRANSPORTE - CASOS NO EXITOSOS
Formulario: Recepción HDR Transporte
Archivo: 002_RecepcionHDRTransporte_NoExitoso.txt
Tipo de prueba: Caja negra / Aceptación

OBJETIVO
Validar los escenarios en los que no se puede concretar la recepción de una Hoja de Ruta de Transporte, ya sea por falta de selección, falta de guías, cancelación de la operación o inexistencia de servicios válidos.

ACLARACIÓN
Estas pruebas se diseñan desde el punto de vista del usuario. No se evalúa código interno, sino entradas, acciones y resultados visibles en pantalla.

CONTROLES PRINCIPALES DEL FORMULARIO
- ComboBox Servicio
- ListView / Grilla de Guías
- Botón Recibir HDR
- Botón Cancelar
- Mensajes de confirmación / validación

CASO DE PRUEBA 1

Nombre:
Recepción HDR sin seleccionar servicio

Objetivo:
Verificar que el sistema no permita recibir una HDR si no se seleccionó un servicio.

Datos de Entrada:
- Servicio: sin seleccionar.

Precondiciones:
- El formulario se encuentra abierto.

Pasos:
1. Abrir el formulario Recepción HDR Transporte.
2. No seleccionar ningún servicio en el combo.
3. Presionar el botón Recibir HDR.

Resultado Esperado:
- El sistema informa que debe seleccionarse un servicio de transporte.
- No se procesa ninguna guía.
- No se modifica ningún estado.
- La grilla permanece vacía o sin cambios.
- El sistema muestra un mensaje de error de validación "Debe seleccionar un servicio de transporte.
- La recepción no se concreta.

Resultado Obtenido:
- El sistema informa que debe seleccionarse un servicio de transporte.
- No se procesa ninguna guía.
- No se modifica ningún estado.
- La grilla permanece vacía o sin cambios.
- El sistema muestra un mensaje de error de validación "Debe seleccionar un servicio de transporte.
- Se debe oprimir el botón Aceptar.
- La recepción no se concreta.

CASO DE PRUEBA 2

Nombre:
Cancelación de la recepción en el mensaje de confirmación

Objetivo:
Verificar que el sistema no procese la recepción si el usuario cancela la confirmación.

Datos de Entrada:
- Servicio: seleccionar un servicio disponible con guías.
- Confirmación: No.

Precondiciones:
- El servicio seleccionado posee guías asociadas.

Pasos:
1. Seleccionar un servicio disponible.
2. Verificar que se carguen guías en la grilla.
3. Presionar el botón Recibir HDR.
4. En el mensaje de confirmación, seleccionar No.

Resultado Esperado:
- La operación se cancela.
- No se modifican estados de guías.
- No se agregan movimientos al historial.
- Las guías continúan visibles o sin modificaciones.
- La recepción no se concreta.

Resultado Obtenido:
- La operación se cancela.
- No se modifican estados de guías.
- No se agregan movimientos al historial.
- Las guías continúan visibles o sin modificaciones.
- La recepción no se concreta.
______________________________


CASO DE PRUEBA 3

Nombre:
Cancelar limpieza del formulario sin recepción

Objetivo:
Verificar que al presionar Cancelar no se modifique información ni se concrete recepción.

Datos de Entrada:
- Servicio seleccionado con guías cargadas.

Precondiciones:
- Existe un servicio seleccionado.
- La grilla contiene guías.

Pasos:
1. Seleccionar un servicio disponible.
2. Verificar que se carguen guías.
3. Presionar el botón Cancelar.

Resultado Esperado:
- Se limpia la selección del servicio.
- Se limpia la grilla.
- No se modifican estados de guías.
- No se registra recepción.
- El formulario queda disponible para una nueva operación.

Resultado Obtenido:
- Se limpia la selección del servicio.
- Se limpia la grilla.
- No se modifican estados de guías.
- No se registra recepción.
- El formulario queda disponible para una nueva operación.

CASO DE PRUEBA 4

Nombre:
Intento de recibir dos veces el mismo servicio

Objetivo:
Verificar que un servicio ya recibido no pueda recibirse nuevamente si ya no posee guías pendientes de recepción.

Datos de Entrada:
- Servicio previamente recibido exitosamente.

Precondiciones:
- El servicio fue recibido correctamente en una prueba anterior.
- Sus guías dejaron de estar pendientes de recepción.

Pasos:
1. Recibir exitosamente un servicio.
2. Desplegar nuevamente el combo Servicio.
3. Intentar seleccionar el mismo servicio recibido.

Resultado Esperado:
- El servicio recibido no aparece nuevamente en el combo.
- No se puede seleccionar para una segunda recepción.
- No se duplican movimientos en el historial.
- No se procesa nuevamente la misma HDR.

Resultado Obtenido:
- El servicio recibido no aparece nuevamente en el combo.
- No se puede seleccionar para una segunda recepción.
- No se duplican movimientos en el historial.
- No se procesa nuevamente la misma HDR.
______________________________


CRITERIO DE ACEPTACIÓN DE LOS CASOS NO EXITOSOS

Los casos no exitosos se consideran aprobados si:
- El sistema muestra mensajes claros cuando falta seleccionar servicio o no hay guías.
- El usuario puede cancelar la operación sin afectar datos.
- No se modifican estados cuando la recepción no corresponde.
- No se listan servicios no válidos para recepción.
- No se permite recibir dos veces la misma HDR.
- El formulario permanece operativo después de cada intento no exitoso.
